🔥 Surasaki’s Matcher

Surasaki’s Matcher — автономный браузерный инструмент для проверки кандидатов по заданным критериям и анализа совместимости wallet.dat.

Проект работает непосредственно в браузере и не требует сервера, установки Node.js или отдельного backend-приложения.

Основная идея проекта — максимально использовать возможности современного JavaScript, WebAssembly, Web Workers и потокового чтения файлов, сохраняя работу даже на мобильных устройствах.

⚡ Проект рассчитан в первую очередь на локальную работу с собственными файлами и данными пользователя.

⸻

✨ Возможности

🎯 Проверка кандидатов

Поддерживаются несколько режимов:

* точное совпадение строки;
* SHA-256 кандидата;
* проверка Bitcoin Core wallet.dat;
* режим только подсчёта пространства поиска.

Кандидаты могут поступать из:

* бинарного словаря SLDB;
* пользовательского перебора по заданному алфавиту.

⸻

🔐 Bitcoin Core wallet.dat

Для совместимого legacy wallet.dat используется существующая криптографическая логика Bitcoin Core:

* mkey;
* ckey;
* nDerivationMethod = 0;
* EVP_BytesToKey;
* SHA-512;
* AES-256-CBC;
* проверка соответствующего ключевого материала;
* дополнительная проверка публичного ключа для строгого подтверждения результата.

Криптографический горячий путь вынесен в WebAssembly.

Анализ wallet.dat

Перед запуском проверки программа анализирует структуру файла и определяет, среди прочего:

* Berkeley DB;
* версию BDB;
* размер страницы;
* количество страниц;
* наличие mkey;
* количество mkey;
* наличие ckey;
* ckeyA;
* hdchain;
* key;
* keymeta;
* name;
* tx;
* состояние шифрования;
* совместимость с текущим verifier.

Это позволяет отличать поддерживаемый wallet от неизвестного или неподходящего формата, вместо того чтобы ошибочно пытаться обработать его старой логикой.

Несколько mkey

Автоматический выбор между несколькими mkey намеренно отключён.

Если в wallet обнаружено несколько master key, программа сообщает:

Manual mkey selection required.

Это предотвращает ситуацию, когда verifier автоматически выбирает неправильный master key и выдаёт некорректный результат.

⸻

📦 Бинарный формат SLDB

Для больших словарей проект использует собственный потоковый формат SLDB v7.

Файл начинается с 32-байтного заголовка:

Offset	Размер	Назначение
0	4	SLDB
4	1	версия 7
5	1	flags
6	2	reserved
8	8	количество записей uint64 LE
16	8	reserved
24	8	reserved

После заголовка идут записи:

4 bytes  — длина записи, uint32 LE
N bytes  — UTF-8 данные

Записи не имеют завершающего NUL.

Конец файла определяется физическим EOF.

Почему SLDB

Главное преимущество — возможность работать с очень большими словарями без загрузки всего файла в оперативную память.

Программа использует потоковое чтение через:

File.slice()

с небольшими блоками данных.

Поэтому даже словари размером в гигабайты не требуют загрузки целиком в RAM.

⚙️ Производительность

Surasaki’s Matcher использует несколько уровней оптимизации.

WebAssembly

Криптографический участок EVP_BytesToKey-SHA512 выполняется в WebAssembly.

Это позволяет значительно сократить стоимость самого горячего участка алгоритма.

Web Workers

Для wallet-проверки поддерживается параллельная обработка.

Каждый Worker имеет собственный экземпляр WASM и собственную память.

Доступно:

Auto
1 Worker
2 Worker
...
10 Worker

Количество Worker можно выбрать вручную либо оставить автоматический режим.

Профили

В программе есть три профиля производительности:

🟢 Эконом

Для устройств с ограниченными ресурсами и меньшим энергопотреблением.

⚖️ Баланс

Рекомендуемый режим для большинства устройств.

🔴 Мощность

Максимальное использование доступных вычислительных ресурсов.

Профиль не меняет криптографический алгоритм. Он определяет параметры выполнения и распределения вычислительной нагрузки.

⸻

📊 Benchmark

В программу встроены несколько видов тестирования.

⚡ Benchmark первых строк

Позволяет быстро оценить реальную скорость обработки кандидатов на текущем устройстве.

🔬 Crypto Diagnostic

Разбивает стоимость проверки кандидата на основные этапы:

* EVP-SHA512;
* AES-CBC;
* проверку ключа;
* вспомогательные операции.

Это позволяет понять, где находится реальное узкое место.

🧪 Crypto Self-Test

Проверяет корректность криптографического WebAssembly и сравнивает результаты с ожидаемыми значениями.

🧪 Worker Benchmark 1–10

Позволяет проверить масштабирование от 1 до 10 Worker и определить оптимальное количество процессов именно для текущего устройства.

🚀 Рабочая зона

Рабочая часть программы предоставляет управление текущей сессией:

⸻

💾 Checkpoint и восстановление

Длительные задачи не должны начинаться заново после случайного закрытия вкладки.

Для этого используется IndexedDB.

Сохраняются данные текущей сессии и позиции обработки.

Поддерживаются:

* pause/resume;
* продолжение после перезапуска;
* экспорт прогресса;
* импорт прогресса;
* сброс текущего состояния.

Для словарей используется сигнатура, учитывающая характеристики файла, поэтому прогресс не должен случайно применяться к другому словарю.

⸻

🧠 Память

Одна из ключевых целей проекта — не загружать большие словари целиком.

Принцип работы:

SLDB file
    ↓
File.slice()
    ↓
небольшой chunk
    ↓
разбор записи
    ↓
кандидат
    ↓
Worker / crypto
    ↓
результат
    ↓
следующая запись

Это особенно важно для мобильных Safari, где доступная память значительно ограничена.

🛡️ Приватность

Программа предназначена для локальной обработки.

Wallet-файлы и словари используются непосредственно в браузере.

* не передавать приватные ключи и пароли третьим лицам;
* работать с резервными копиями;
* не запускать неизвестные модификации приложения.

⚠️ Ограничения

Текущий verifier ориентирован на совместимый с ним класс legacy Bitcoin Core wallet.dat.

Наличие файла с расширением .dat само по себе не означает, что он является поддерживаемым Bitcoin Core wallet.

Если анализ определяет неизвестный или несовместимый формат, программа не должна автоматически трактовать его как стандартный wallet.

Также не все современные типы Bitcoin-кошельков используют старую схему mkey/ckey + EVP_BytesToKey-SHA512 + AES-256-CBC.

⸻

🔒 Безопасность и корректность

Криптографическая проверка должна подтверждаться не одним случайным совпадением байтов.

Для поддерживаемого wallet используется последовательность:

candidate
   ↓
EVP_BytesToKey-SHA512
   ↓
AES-256-CBC
   ↓
проверка расшифрованного master key
   ↓
проверка соответствующего ckey
   ↓
secp256k1 / public-key validation
   ↓
FOUND

Таким образом, FOUND означает подтверждённый результат, а не просто успешное прохождение одного промежуточного этапа.
